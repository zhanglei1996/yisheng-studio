# 编辑器整体产品审查（2026-08-14）

## 审查范围

- 页面：macOS 编辑器主工作区。
- 用户目标：发现并处理生成问题，校对单个片段，完成时间线编辑，安全进入导出。
- 证据：用户提供的真实项目截图，以及本地 Browser 中的实现态、紧凑窗口态和导出预检态。

## 总体判断

现有专业暗色剪辑器骨架、四轨时间线和三栏分工成立。主要问题不是功能不足，而是异常入口重复、混合问题时主动作优先级错误、静态工具伪装成按钮，以及当前片段缺少持续可见的序号与导航。

## 流程审查与处理

1. 进入编辑器并扫描项目风险：原状态同时显示配音失败与时长提醒，但横幅主动作只处理时长问题，左侧又重复一次批量修复。已改为“阻断优先”，混合状态同时列出两类数量，失败片段为主动作；左侧只保留定位入口。健康度：由“主次混乱”调整为“清晰”。
2. 选择并校对片段：文本、声音、对齐三类面板完整，但用户难以确认当前是第几个片段，也只能回到播放器或时间线切换。已增加 `片段 N / 总数`、状态标签和前后导航，并保留上下方向键。健康度：由“可用但低效”调整为“良好”。
3. 使用时间线工具：蓝色选择图标没有点击行为，拆分和合并在无效条件下仍呈可用态，锁定片段仍可从状态层执行拆分。已删除静态选择状态，按未选择、过短、末尾和边界锁定禁用工具并提供原因，同时补齐状态层锁定保护。健康度：由“有误导风险”调整为“良好”。
4. 处理全局高影响动作：重新翻译全部字幕会覆盖现有译文并向第三方发送文本，但原入口直接执行。已增加确认说明，明确覆盖范围、第三方文本传输和原视频/原声不上传。健康度：由“高风险直达”调整为“受控”。
5. 进入导出：保留导出预检，不把有提醒的项目伪装成可直接发布；阻断态按钮改为“导出检查”，提示点击后查看问题。Browser 中已验证提醒态能进入导出预检，并可返回自动修复。健康度：良好。

## 可访问性风险与处理

- 删除了不可聚焦、无按钮语义却使用激活按钮外观的选择状态。
- 前后片段、锁定边界、吸附、拆分和合并均有可访问名称；禁用工具保留原因提示。
- 阻断横幅使用 `alert`，非阻断提醒使用 `status`；片段状态不只依赖颜色。
- 本轮未进行完整屏幕阅读器、200% 文本缩放或全键盘 WCAG 验证，因此不声明完整无障碍合规。

## 证据限制

Browser 回退数据包含 4 个片段和 1 个时长提醒；用户截图中的“配音失败 + 时长提醒”混合态以当次截图和实现条件分支为依据，没有在浏览器回退数据中重放真实服务商失败。
