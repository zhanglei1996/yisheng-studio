## 导出过程可见进度

- 来源：真实样片导出体验，导出弹窗在较长时间内仅显示“正在准备导出”的按钮 loading 状态。
- 问题：用户无法判断导出是否仍在工作、当前处于什么阶段、预计还需多久，也没有明确的取消反馈。
- 优化目标：在导出弹窗内显示持续更新的进度区，而非只有按钮 loading。
- 建议交互：
  - 显示总体百分比和当前阶段，例如“生成字幕”“混合音轨”“编码视频”“写入文件”。
  - 编码阶段显示已处理时长 / 总时长；可用时补充预计剩余时间。
  - 保留“取消导出”动作，取消后清楚说明已保留哪些可复用产物、已清理哪些临时文件。
  - 完成后自动切换为成功状态，展示导出目录与“在 Finder 中显示”。
- 技术前提：FFmpeg 导出进程需启用可解析的进度输出，并通过 `export://progress` 事件传给前端；任务队列和导出弹窗复用同一进度来源。
- 验收：10 分钟以上视频的导出过程中，用户在 1 秒内能看到当前阶段及进度变化；取消、失败和完成三种状态均有明确结果提示。

## 导出完成后打开保存位置

- 来源：真实样片导出完成页。
- 问题：“查看保存位置”当前只展示或复制结果路径，用户还需要自行切换到 Finder 查找导出包。
- 优化目标：点击“查看保存位置”后直接在 macOS Finder 中打开导出目录；如平台允许，优先选中导出的中文配音视频。
- 建议交互：
  - 主动作命名为“在 Finder 中显示”，配合文件夹图标。
  - Finder 无法打开时保留可复制完整路径，并给出非阻断错误提示。
  - 结果页持续显示导出目录，方便用户确认位置。
- 技术前提：通过受控的 Tauri/Rust 命令调用 macOS Finder；前端只传递已由导出任务生成并校验过的产物路径，不执行任意 Shell。
- 验收：导出成功后点击一次即可打开对应文件夹；目标视频存在时在 Finder 中高亮该文件。

## 中文配音自然度与在线 TTS

- 来源：真实英文技术视频的完整中文试听。
- 结论：当前 macOS 系统语音（Tingting）发音生硬、语气与停顿单一，无法达到技术课程可持续观看的听感，不适合作为正式导出的默认声音。
- 优先级：高。
- 产品决策：macOS 系统语音只保留为零配置、离线可用的兜底与链路验证方案；正式使用默认推荐用户配置高质量中文神经 TTS。
- 首批候选：讯飞语音合成优先，其后接入腾讯云 TTS；均使用用户自备凭据、由桌面应用直连服务商。
- 建议体验：
  - 服务商页提供声音列表、短句试听、情感/风格（若 Provider 支持）、语速和音色说明。
  - 创建项目时明确标记“系统语音（基础）”与“神经语音（推荐）”。
  - 导出前提示正在使用基础系统语音，允许直接跳转配置高质量 TTS，但不阻断本地离线导出。
  - 支持按项目及片段覆盖声音与语速，局部重生成不重做整条视频。
- 技术前提：实现统一 `TtsProvider` 适配层，覆盖连接测试、声音列表、试听、片段合成、错误与限流处理；Key 继续保存在 macOS Keychain，不写入 SQLite 或日志。
- 验收：同一段 30～60 秒技术课程中，讯飞等神经语音在语气、停顿与可懂度上显著优于系统语音；可完成单片段替换、时长适配和完整导出。

## 本地处理资源占用与可观测性

- 来源：导出后观察到 macOS CPU 占用偏高。
- 本次排查结论：检查时译声工坊 CPU 为 0%，未发现 FFmpeg、whisper、`say` 或人声分离 worker 在运行；当时主要负载来自 Codex Renderer / GPU 进程、ClashX 与 WindowServer。因此截图中的高 CPU 不是当前项目的媒体处理直接造成。
- 优化目标：即使后续真实 ASR、TTS、分离或导出确实占用资源，用户也能知道“哪个阶段、哪个本地 worker、占用了多少资源”，并能主动降低负载。
- 建议体验：
  - 任务队列显示当前 worker（ASR / TTS / FFmpeg 导出）、阶段级 CPU 与内存占用、已运行时间。
  - 设置中提供“节能 / 平衡 / 最快”预设，控制并发数、whisper 线程数与 FFmpeg 编码并发。
  - 长任务支持暂停、取消和重启后恢复；取消时可靠终止子进程，避免后台残留。
  - 处理开始前明确提示预计资源影响；完成、失败或取消后自动回收 worker 与临时资源。
- 技术前提：Rust 进程管理层记录 Sidecar PID、启动/退出原因、资源采样与任务关联；诊断信息不包含视频正文、音频、字幕或 API Key。
- 验收：用户可在应用内确认当前是否存在本产品的重型 worker；暂停/取消后对应子进程在合理时间内退出；节能模式下资源上限符合设定。

## 项目库使用真实视频封面

- 来源：真实项目库截图。当前已导入的视频仍展示固定的 RAG 示例封面，和项目内容不一致。
- 优化目标：每个真实项目显示从对应视频提取的真实封面帧；固定示例图只用于浏览器演示数据或尚未选择媒体的空状态。
- 建议实现：
  - 媒体准备阶段通过 FFmpeg 从源视频或预览代理提取一张稳定关键帧，默认取视频 3% 处并限制在 2～10 秒范围内，避免黑场开头。
  - 输出固定尺寸的本地 JPEG/WebP 缩略图，作为项目产物记录路径与依赖哈希。
  - 若默认帧接近黑场或空白，自动尝试后续候选时间点；失败时使用中性媒体占位图，不回退到不相关的课程示例图。
  - 项目库通过 Tauri asset protocol 加载缩略图，原始视频不复制、不上传。
- 验收：导入任意本地视频后，项目卡片在媒体准备完成时显示该视频实际画面；源文件变化或重新关联后封面按依赖失效规则更新。

## 时间轴横向滚动与导航

- 来源：真实编辑器截图。当前时间轴仅根据选中片段/播放头动态切换可视区，缺少用户主动左右浏览整条视频的连续操作。
- 优化目标：时间轴应像剪辑工具一样支持独立的横向视口，可平滑查看任意时间段，而不是只能被动跳转。
- 建议交互：
  - 鼠标滚轮 + Shift、触控板横向手势、底部水平滚动条均可左右平移时间轴。
  - 手型工具可拖拽画布平移；点击标尺或轨道仍用于定位播放头，避免与拖拽冲突。
  - 缩放以鼠标位置或当前播放头为锚点，缩放后保留用户正在查看的时间位置。
  - 提供“回到播放头 / 选中片段”快捷动作；播放时可选择自动跟随或取消跟随。
  - 虚拟化超长视频的片段与波形，只渲染当前视口附近内容，保证 1 小时项目也保持流畅。
- 技术前提：将 `viewStartMs` 从选中片段派生值改为独立、可持久化的时间轴视口状态，并建立滚动/缩放/播放头的同步规则。
- 验收：用户可从 00:00 连续横向浏览至任意时点；缩放、拖动片段和播放头跟随不抖动，长视频操作保持流畅。
