# 译声工坊“可发布配音”改造计划

> 状态：实施中（安全模式 MVP 已落地）
>
> 日期：2026-08-13
>
> 适用范围：英文技术讲解、屏幕录制、演示动画等非强口型视频

## 1. 背景与问题

当前链路已经能完成识别、翻译、中文口播、时长适配、字幕和视频导出，但“成功导出”还不等于“可发布”。真实样片暴露出四个彼此耦合的问题：

1. **语言不连贯**：字幕片段同时承担翻译、TTS 和同步三种职责，口播被切得过碎，语气频繁重新启动。
2. **连贯与同步冲突**：整段生成更自然，但中文语序和英文语序不同，逐字幕时间窗无法同时保证自然表达和机械对齐。
3. **低信息画面没有参与时长适配**：系统只压缩文案或改变语速，不能裁剪、加速或延长静止画面。
4. **原声语义被破坏**：静音原声模式会一并删除音乐、点击声和环境声，使正常的画面停留变成“死寂”。

样片中的典型证据：

- `08:23.20–08:41.24` 出现约 18 秒连续静音，期间画面仍在执行应用启动和页面操作。
- 片尾字幕包含“[音乐播放中]”，实际成片音乐已被删除。
- 162 条配音同步字幕中有 5 条短于 700ms，最短只有 180ms。
- 源视频约 42MB，烧录字幕后的成片约 417MB，发布成本明显膨胀。

根本原因是当前系统仍以 `SegmentRecord` 为中心，把原字幕边界当成所有下游处理的硬边界。改造需要引入比字幕片段更高一级的“场景”，并让视频时间本身成为可编辑资源。

## 2. 产品目标

将译声工坊从“逐字幕中文替换工具”升级为“面向可发布成片的弹性本地化编辑器”。

核心原则：

- **场景内语言自然连贯，关键语义与关键画面同步。**
- **同步的是观众认知，而不是中英文逐句时间码。**
- **优先压缩低信息时间，不牺牲语义、操作因果和自然语速。**
- **所有视频改动非破坏、可预览、可撤销，并保持原文件不变。**
- **音乐、环境声和操作声是成片内容，不应随原语言人声一起被删除。**

### 2.1 成功标准

- 15–30 秒场景的中文口播听起来像一次连续讲述，而不是多个 TTS 片段拼接。
- `exact` 锚点对应短语与关键画面的偏差不超过 ±500ms；`near` 锚点不超过 ±1200ms。
- 默认不产生短于 800ms 的烧录字幕，且不产生相邻字幕重叠。
- 所有超过 3 秒的成片静音都有明确来源：创作选择、原视频静音，或发布前风险提示。
- 低信息区间可通过裁剪或加速压缩，并能正确联动视频、音频、字幕和锚点时间。
- 普通用户能够接受系统建议并一键生成；专业用户能够逐项复核和撤销。

### 2.2 非目标

- 本阶段不做人物口型生成或逐音素唇形同步。
- 不建设完整多轨 NLE，不支持任意转场、调色、特效和复杂关键帧。
- 不自动重剪高信息人物表演、访谈或剧情视频。
- 不默认直接修改源视频文件。

## 3. 目标工作流

```text
导入视频
  → ASR、非语言事件与镜头/画面变化分析
  → 形成语义场景和视觉锚点
  → 生成场景级中文口播
  → 场景级 TTS + 字词时间戳
  → 计算音画适配方案
       ├─ 调整停顿
       ├─ 小幅语速调整
       ├─ 裁剪低信息画面
       ├─ 加速操作/等待画面
       ├─ 延长静态结果画面
       └─ 重新改写口播
  → 用户预览并确认时间变换
  → 保留音乐/SFX 的混音
  → 发布质量检查
  → 导出
```

“快速生成”默认自动采用低风险建议；“先校对”展示所有场景、锚点和画面变换供用户确认。两种模式使用同一底层时间模型，避免产生两套不可兼容的工程链路。

## 4. 核心产品模型

### 4.1 三种粒度分离

| 粒度 | 职责 | 是否直接送入 TTS |
| --- | --- | --- |
| 原始片段 `Segment` | ASR 证据、原文和逐句字幕 | 否 |
| 语义场景 `NarrationScene` | 连贯翻译、口播和时长预算 | 是，一场景一次 |
| 同步锚点 `SyncAnchor` | 约束关键短语与关键画面的关系 | 作为 TTS/对齐约束 |

原始片段继续作为可追溯证据和字幕校对单元，但不再决定 TTS 的切口。

### 4.2 场景模型

建议新增持久化实体：

```ts
interface NarrationScene {
  id: string;
  projectId: string;
  ordinal: number;
  sourceStartMs: number;
  sourceEndMs: number;
  segmentIds: string[];
  subtitleZh: string;
  spokenZh: string;
  durationBudgetMs: number;
  status: "draft" | "ready" | "warning" | "blocked";
  revision: number;
}
```

场景建议长度为 12–30 秒，优先在镜头切换、页面切换、标题出现、长静音或语义段落结束处断开。不得只按固定秒数切分。

### 4.3 锚点模型

```ts
interface SyncAnchor {
  id: string;
  sceneId: string;
  sourceTimeMs: number;
  phrase: string;
  kind: "visual" | "action" | "speech" | "non_speech";
  priority: "exact" | "near" | "free";
  toleranceMs: number;
  confidence: number;
  locked: boolean;
}
```

- `exact`：点击、页面切换、结果出现等强因果事件。
- `near`：加载模型、启动服务、进入下一步等阶段性表达。
- `free`：背景解释、铺垫和总结，只需位于场景内。
- `non_speech`：音乐、掌声、点击声、环境声等，不生成 TTS。

### 4.4 非破坏视频编辑模型

不能把裁剪后的时间直接写回所有原始时间码。新增编辑决策列表 EDL：

```ts
interface TimelineEdit {
  id: string;
  projectId: string;
  sourceStartMs: number;
  sourceEndMs: number;
  operation: "keep" | "cut" | "speed" | "freeze";
  rate?: number;
  outputDurationMs: number;
  origin: "automatic" | "user";
  reason: string;
  confidence: number;
  accepted: boolean;
}
```

EDL 是源时间到成片时间的唯一映射来源：

```text
sourceTime ── TimelineMap(EDL) ──> outputTime
```

视频帧、源音频、场景、字幕和锚点都通过同一 `TimelineMap` 转换。修改任一编辑项后，映射重新计算；原始 ASR 和源时间始终保持不变。

### 4.5 非语言事件

新增 `NonSpeechEvent`，至少支持：

- music
- applause
- click
- typing
- ambience
- unknown

`[MUSIC PLAYING]` 一类 ASR 结果应转换为事件而不是 `spokenZh`。事件可进入字幕，但永远不进入 TTS。

## 5. 音画适配决策引擎

### 5.1 决策顺序

每个场景完成 TTS 后，根据实际音频时长、字词时间戳和锚点误差依次处理：

1. 调整句间停顿和场景内起始位置。
2. 在 `0.94×–1.06×` 内小幅调整语速。
3. 若中文偏短，压缩低信息画面；若中文偏长，延长静态结果画面。
4. 仍不满足时，按时长预算重新生成口播。
5. 锚点仍超差则标记 `blocked`，由用户处理。

不得直接用无限制 `atempo` 强制塞入原窗口。超过 12% 的时长差异应优先改稿或调整画面；超过 20% 通常说明场景边界或翻译策略有问题。

### 5.2 低信息区间检测

候选区间需综合以下信号：

- 连续帧相似度高、结构变化小。
- 没有镜头切换、显著动画和新增文字。
- 鼠标没有关键移动或点击。
- 原讲话已结束，下一语义段尚未开始。
- 没有被锁定的视觉锚点。
- 音轨中没有必须保持完整的音乐节拍或事件。

建议等级：

| 区间情况 | 默认动作 |
| --- | --- |
| 少于 500ms | 不处理 |
| 500–1200ms | 默认保留为呼吸时间 |
| 1200–3000ms 且画面静止 | 建议裁剪，保留 350–600ms |
| 操作或加载仍在继续 | 建议 1.5×–3× 加速 |
| 超过 3000ms | 标为高价值压缩候选，需预览确认 |
| 人物口型、表演或关键动画 | 禁止自动裁剪 |

每个切口前后保留稳定帧，并对连续音频使用短交叉淡化，避免爆音和突变。

### 5.3 画面延长

中文仅略长于画面时，可以冻结或延长低动态结果页，但需要满足：

- 延长点不是人物画面。
- 没有光标闪烁、进度条或明显循环动画。
- 单次默认不超过 1500ms。
- 延长后仍保留下一视觉事件的因果关系。

### 5.4 锚点对齐

TTS Provider 优先返回字、词或音素时间戳。若 Provider 不支持，则使用本地强制对齐或音频静音边界作为降级方案。

适配器输出统一为：

```ts
interface WordTiming {
  text: string;
  startMs: number;
  endMs: number;
  confidence: number;
}
```

引擎根据 `phrase` 在 `WordTiming[]` 中定位关键短语，计算其实际位置与目标输出时间的偏差。先移动停顿和场景起点，再考虑变速、画面编辑或改稿。

## 6. 连贯口播生成

### 6.1 场景级输入

翻译模型输入应包含：

- 场景内完整原文和原字幕。
- 前一个场景的结尾摘要与下一个场景的开头摘要。
- 术语表和受保护模型名。
- 场景时长预算。
- 锚点短语、目标时间和优先级。
- 非语言事件，明确禁止口播。

输出必须区分完整字幕和精简口播，并返回锚点短语映射。技术专名如 `ChatGPT`、`RAG`、`ChromaDB`、`Flask`、`all-MiniLM-L6-v2` 必须经过术语保护和读法规范化。

### 6.2 TTS 合成

- 每个场景只合成一次完整口播。
- 场景间传入相同声音、风格、语速和可用的上下文指令。
- 场景边界使用 15–40ms 淡入淡出；必要时使用极短交叉淡化。
- 只有修改场景稿、声音、锚点或时间编辑时才使相关场景及下游产物失效。
- 快速模式可以自动重新合成，但必须设定重试和费用上限。

## 7. 原声与混音改造

现有 `mute` 与固定 `volume=0.16` 不能满足发布需求。原声处理改为三层：

1. **原语言人声层**：静音、duck 或分离后移除。
2. **音乐/SFX 层**：尽量保留原立体声。
3. **中文人声层**：居中、响度统一、根据需要触发 sidechain ducking。

“安全模式”不使用“无说话区间恢复完整原声”的策略。ASR/VAD 边界存在误差，恢复完整原声会在漏检区间、词尾或长停顿中突然重新出现英文。MVP 采用以下硬约束：

- 导入后在本机将完整立体声音频分为人声与 `Instrumental` 背景轨。
- 预览、时间线编辑和导出全程只消费背景轨与中文配音，不在任何区间恢复完整原声。
- 背景轨随 `TimelineMap` 应用同一裁剪/加速映射，因此点击、音乐和画面保持同步。
- 分离组件缺失、模型失败、源文件指纹变化或缓存清单过期时，媒体准备失败且导出预检阻断；禁止降级为 duck 或回混原声。
- `mute` 模式只输出中文配音；`duck` 作为明确标注“可能听见英文”的兼容选项保留。

当前本地实现使用应用数据目录中的 `audio-separator 0.44.5` 与 `UVR-MDX-NET-Inst_HQ_3.onnx`，分离结果和源文件指纹、模型版本绑定。原视频和原音频不为分离上传到第三方。

发布预设建议默认输出 48kHz 立体声，并在最终混音后执行响度归一化和真峰值限制。具体目标作为预设参数，不写死在业务代码中。

## 8. 编辑器体验

继续保持专业深色四轨时间线，但增加两条语义能力：

- **场景/锚点轨**：显示场景边界、`exact/near/free` 锚点及误差。
- **画面变换轨**：显示裁剪、加速、冻结区域和预计节省时长。

### 8.1 核心交互

- “优化音画同步”扫描后给出建议数量、预计缩短时间和风险等级。
- 选择建议后支持裁剪前/后循环对比，播放头保持在同一认知事件附近。
- 用户可接受、拒绝、调整保留时长或锁定区间。
- 修改一个裁剪项后，时间线执行涟漪更新，但源时间可随时查看。
- 场景检查器同时显示：口播时长预算、实际 TTS 时长、语速、锚点误差和建议动作。
- 提供“一键恢复本场景原始画面”和“撤销全部自动优化”。

### 8.2 快速模式与校对模式

快速模式只自动接受：

- 高置信度静态区间裁剪。
- 不跨锚点、不含人物、单次缩短不超过安全阈值的建议。
- 小幅停顿和语速调整。

下列情况必须进入复核：

- 单次裁剪超过 3 秒。
- 存在 `exact` 锚点偏差。
- 涉及人物画面或无法识别的运动。
- 场景需重写两次以上仍无法适配。
- 背景音乐可能在切口处发生明显跳变。

## 9. 发布质量门禁

当前 `ExportPreflight` 只检查配音是否生成和是否存在超窗警告，需要升级为结构化检查项：

```ts
interface PublishCheck {
  code: string;
  severity: "blocking" | "warning" | "info";
  sourceRange?: [number, number];
  outputRange?: [number, number];
  sceneId?: string;
  message: string;
  suggestedAction?: string;
}
```

首批规则：

- `unexpected_silence`：源音频有内容但成片静音超过阈值。
- `non_speech_spoken`：音乐/掌声等事件进入 TTS。
- `anchor_drift`：锚点误差超过容忍度。
- `caption_flash`：字幕短于 800ms。
- `caption_reading_speed`：字幕阅读速度过高。
- `unnatural_speed`：语速调整超过安全范围。
- `hard_cut_audio`：音频切口没有淡化或能量突变过大。
- `term_risk`：受保护术语被翻译或疑似 ASR 错误。
- `channel_loss`：源视频有立体声内容而成片无合理原因降为单声道。
- `size_inflation`：预计成片体积相对源文件异常膨胀。

导出弹窗需区分阻断项和可接受警告，允许用户点击检查项直接定位时间线。

### 10.3 缓存与依赖

建议建立以下依赖链：

```text
source fingerprint
  → ASR / non-speech / visual analysis
  → scene revision + anchors
  → narration revision
  → TTS audio + word timings
  → timeline edit revision
  → timeline map
  → mixed preview
  → publish checks
  → export
```

改变裁剪只应使时间映射、预览、发布检查和导出失效，不应重新执行 ASR 或翻译；改变场景口播只使该场景 TTS 及其下游失效。

## 11. 分阶段实施计划

### Phase 0：基线与契约（约 3–5 个开发日）

目标：先让问题可测量，避免在主观听感上盲目迭代。

- 固化 3–5 支不同类型的合法测试视频：动画讲解、屏幕操作、人物讲解。
- 记录当前场景连续性、锚点偏差、长静音、字幕闪烁、体积和导出耗时。
- 确定 Scene、Anchor、EDL 和 PublishCheck 数据契约。
- 为现有项目提供无损数据库迁移；未生成场景时继续走旧链路。

退出条件：时间映射契约和测试样片基线可重复生成。

### Phase 1：场景级连贯配音（约 7–10 个开发日）

目标：先解决语言连贯性，不立即改视频长度。

- 自动形成 12–30 秒语义场景，支持用户合并/拆分。
- 场景级翻译和一次性 TTS。
- 保存统一字词时间戳；Provider 不支持时启用降级对齐。
- 中文字幕改由真实发音时间生成，并消除闪烁字幕。
- 上线 `nonSpeechEvent`，阻止 `[MUSIC]` 等进入 TTS。

退出条件：样片中场景内无可感知的 TTS 重启感；字幕最短时长规则通过。

### Phase 2：锚点同步与弹性适配（约 7–10 个开发日）

目标：使场景级自然口播仍能命中关键画面。

- 自动提取视觉/动作锚点，并支持手动增删、拖动和锁定。
- 实现锚点短语定位和误差计算。
- 实现停顿移动、小幅变速、场景平移和按预算重写。
- 编辑器展示锚点误差和可执行建议。
- `exact` 锚点超差时阻止静默导出。

退出条件：基准样片的关键动作达到锚点误差目标，且语速不超过安全范围。

### Phase 3：低信息画面压缩（约 10–15 个开发日）

目标：把视频时间也纳入适配，先从安全的静态区间开始。

- 实现 `TimelineMap`、EDL 持久化及双向时间映射。
- 检测静态/低信息候选区间。
- 支持 `cut` 和 `speed`；`freeze` 可作为后续子阶段。
- 提供裁剪前/后对比、接受/拒绝、撤销和涟漪时间线。
- 导出器按 EDL 同步变换视频、源音频、字幕和锚点。

退出条件：删除任一区间后，全链路时间一致；不发生锚点穿越、字幕漂移或音频爆点。

### Phase 4：音轨分层与发布门禁（约 7–12 个开发日）

目标：从“生成完成”升级为“发布就绪”。

- 已上线安全模式本地人声分离，默认保留去人声背景轨中的音乐/SFX。
- 不在无口播区恢复完整原声；分离不可用时阻止导出。
- 实现结构化 PublishCheck 与时间线定位。
- 增加响度、真峰值、声道、长静音和体积检查。
- 导出预设替代固定 6000k，提供预计体积。

退出条件：样片的异常静音、音乐丢失和字幕闪烁不再通过发布门禁；体积处于所选预设的合理区间。

## 12. MVP 范围建议

首个可交付版本建议只包含：

1. 场景级口播和 TTS。
2. 非语言事件过滤。
3. `exact/near/free` 锚点与误差提示。
4. 静态区间的非破坏裁剪，不做复杂光流补帧。
5. 安全模式本地人声分离，只混合去人声背景轨与中文配音。
6. 长静音、字幕闪烁、锚点偏差和术语风险四类发布检查。

暂缓：自动冻结、人物视频自动剪辑、音乐节拍感知和任意多轨编辑。这样可以优先验证“连贯＋同步＋低信息裁剪＋无英文残留”是否真正改善用户体验。

## 13. 测试与验收

### 13.1 单元与性质测试

- EDL 必须覆盖完整源时间，区间有序、无重叠、无负时长。
- `source → output → source` 在可逆区间内误差不超过 1ms。
- 裁剪区间内的源时间返回明确的 deleted 状态，不伪造映射。
- 任意编辑组合后，输出时长等于所有 `outputDurationMs` 之和。
- 场景、字幕和音频不得穿越被锁定的锚点。
- 局部修改只失效预期的依赖产物。

### 13.2 媒体验证

- `ffprobe` 校验音视频总时长差不超过一帧或一个 AAC packet 的合理范围。
- 检测空帧、冻结异常、音频削波、硬切爆点和非预期静音。
- 对裁剪前后关键帧生成接触表，确认没有跳过必要操作。
- 比较源音频与成片非语言能量，确认音乐/SFX 没有无故消失。

### 13.3 体验验收

每支基准视频至少由两名中文母语用户盲听/盲看：

- 语言连贯性。
- 语速自然度。
- 关键动作与解说是否同步。
- 跳切是否可感知或破坏理解。
- 是否出现无缘由的死寂。

自动指标只用于发现风险，不能替代最终完整试听。

### 13.4 仓库验证

- 开发过程中运行 `pnpm verify:fast`。
- 阶段交付前运行 `pnpm verify:full` 和真实视频交互检查。
- 涉及产品设计的阶段同步更新 `design-qa.md`，保留裁剪前/后、锚点和发布检查的视觉对比证据。
- 只有用户明确需要独立 App 包时才运行 `pnpm verify:release`。

## 14. 迁移与兼容策略

- 旧项目默认 `timeline_edit_revision = 0`，等价于整片 `keep`，导出行为保持兼容。
- 首次启用“智能同步”时生成场景、锚点和 EDL，不改写现有 `SegmentRecord`。
- 保留“传统逐片段同步”作为一段时间内的回退路径。
- 新增模型使用版本号，分析或算法更新不应偷偷改动用户已经接受的裁剪。
- 自动建议与用户接受状态分离；重新分析可以产生新建议，但不得覆盖用户决定。

## 15. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 自动裁剪删掉重要画面 | 默认只建议；人物和低置信度区间禁止自动接受；支持循环对比与撤销 |
| 画面裁剪导致音乐跳变 | 音频切口交叉淡化；有明显音乐时降低置信度并要求复核 |
| 场景级 TTS 成本上升 | 缓存场景结果；局部失效；限制自动改稿与重试次数 |
| 字词时间戳供应商差异 | Provider 能力声明；统一 `WordTiming`；本地对齐降级 |
| EDL 引发全链路复杂度 | 唯一 `TimelineMap` 服务；禁止各模块自行累计时间偏移 |
| 快速模式做出不可见决定 | 导出前摘要所有自动裁剪、加速、改稿和警告 |
| 长视频分析耗时 | 使用代理视频、分层采样、缓存视觉特征并支持暂停恢复 |

## 16. 最终产品判断

这次改造的重点不是单独增加“裁剪视频”按钮，而是建立一个统一的弹性同步系统：

- 文案通过场景级生成获得连贯性；
- 关键语义通过锚点保持认知同步；
- 低信息画面通过非破坏裁剪或加速提供时长弹性；
- 音乐和操作声负责承接自然留白；
- 发布门禁阻止技术上成功、体验上失败的成片。

只有这五部分共享同一时间映射和依赖模型，视频裁剪才不会成为新的字幕漂移、音频错位和缓存失效来源。
